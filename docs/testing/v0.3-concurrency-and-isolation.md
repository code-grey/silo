# Silo Verification Lab: Concurrency, OverlayFS & Resource Isolation

This lab guides developers through verifying that Silo's Linux kernel primitives—Namespaces, Cgroups v2, and OverlayFS—behave correctly under concurrent, multi-container workloads.

---

## Prerequisites
1. Ensure the Alpine base image is installed:
   ```bash
   ./scripts/setup_rootfs.sh
   ```
2. Build the runtime:
   ```bash
   cd silo-core && go build -o silo . && cd ..
   ```
3. Open **three terminal windows** side-by-side:
   - **Terminal 1:** Container A
   - **Terminal 2:** Container B
   - **Terminal 3:** Host OS Observer

---

## Lab 1: The "Ghost Filesystem" Test (OverlayFS Isolation & Ephemerality)

**Objective:** Prove that two concurrent containers running off the exact same base image cannot see each other's changes, and neither mutates the host's base image.

### Step 1: Boot Container A
In **Terminal 1**, run:
```bash
cd silo-core && sudo ./silo run /bin/sh
```
Inside Container A, create a file:
```sh
echo "Secret data from Container A" > /container_a.txt
ls -l /container_a.txt   # File exists!
```

### Step 2: Boot Container B
In **Terminal 2**, run:
```bash
cd silo-core && sudo ./silo run /bin/sh
```
Inside Container B, attempt to find Container A's file:
```sh
ls /container_a.txt
```
* **Expected Result:** `ls: /container_a.txt: No such file or directory`
* **Why it works:** Container A's writes are confined entirely to its own ephemeral `upperdir`. Container B has its own independent `upperdir` and only shares the read-only `lowerdir`.

### Step 3: Check Host Base Image
In **Terminal 3 (Host OS)**:
```bash
ls /tmp/silo-container/rootfs/container_a.txt
```
* **Expected Result:** File does not exist on the host. The base image remains 100% pristine.

## Lab 2: The PID 1 Parallel Universe (Process Isolation)

**Objective:** Verify that each container has its own isolated PID 1 namespace and cannot see or signal processes running in other containers.

### Step 1: Spawn Background Task in Container A
In **Terminal 1 (Container A)**:
```sh
sleep 9999 &
ps
```
* Notice that `/bin/sh` is **PID 1**, and `sleep` is **PID 2** (or 3).

### Step 2: Inspect Processes in Container B
In **Terminal 2 (Container B)**:
```sh
ps
```
* **Expected Result:** Only Container B's own processes (`sh` and `ps`) are visible. Container A's `sleep` process is completely invisible.

---

## Lab 3: The "Blast Radius" Test (Cgroup OOM Independence)

**Objective:** Prove that when Container A runs out of memory and crashes, Container B remains completely unaffected and unharmed.

1. Keep both **Container A** (Terminal 1) and **Container B** (Terminal 2) running.
2. In **Terminal 1 (Container A)**, trigger memory exhaustion using the string-doubling loop:
   ```sh
   x=a; while true; do x=$x$x; done
   ```
3. Watch Container A get terminated by the Linux OOM killer:
   ```text
   ================== SILO CATASTROPHE POST-MORTEM ==================
   CRITICAL: Container was terminated by the Linux OOM Killer!
   • Failure Cause : Memory ceiling exceeded (52428800 bytes / ~50 MB)
   • Peak Memory   : 52428800 bytes
   • OOM Kills     : 1
   ==================================================================
   ```
4. Now switch to **Terminal 2 (Container B)**:
   ```sh
   echo "Still alive!"
   ```
* **Expected Result:** Container B continues executing smoothly without interruption. Because each container is allocated an independent `/sys/fs/cgroup/silo-<pid>` slice, failures are completely isolated.

## Lab 4: The Host Inspector View (Storage & Cgroups)

**Objective:** Inspect the live Linux kernel data structures while multiple containers are running simultaneously.

### Step 1: Boot Both Containers
Ensure both Container A (Terminal 1) and Container B (Terminal 2) are booted into `/bin/sh`.

### Step 2: Inspect from Host OS
In **Terminal 3 (Host OS)**:
```bash
# 1. View active Cgroup slices
ls -d /sys/fs/cgroup/silo-*
# Output: Two distinct per-container cgroup directories

# 2. View active OverlayFS instance directories
ls -d /tmp/silo/instances/inst-*
# Output: Two distinct ephemeral instance directories (each with upper, work, merged)
```

### Step 3: Teardown Verification
Exit Container A (type `exit` in Terminal 1), but keep Container B running.
Re-run the commands in Terminal 3:
* Container A's cgroup and overlay instance directory are **cleanly deleted**.
* Container B's instance remains active until it terminates.
