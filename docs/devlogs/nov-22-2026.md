## 2. Kernel Observation: The `limit_hit_max = 38` Phenomenon
- **Observation:** In the verified test run, `limit_hit_max` recorded a value of **38** rather than 1.
- **Kernel Deep Dive:** In Linux Cgroups v2, when an allocation breaches `memory.max`, the kernel does not instantly kill the process. Instead, it enters **direct memory reclamation**:
  1. The kernel pauses the executing thread.
  2. It attempts to scavenge memory by shrinking page caches, dropping clean disk buffers, and compacting memory pages.
  3. Each time an allocation touches the ceiling, the `max` counter in `memory.events` increments.
- **Conclusion:** The kernel attempted to reclaim memory 38 distinct times before exhausting all options and invoking the OOM Killer. This confirms Cgroups v2 memory throttling and event tracking are functioning precisely as designed.

## 3. Daemonless High-Performance Roadmap Expansion
Outlined architectural strategies to achieve sub-millisecond execution speeds without requiring a persistent background daemon:

## 4. Smart Pre-Flight Inspection & Multi-Language Engine (v0.3.1)
- **Eliminating the `ENOEXEC` Trap:** The Linux kernel rejects shebang-less text files with `ENOEXEC` (Exec format error). Silo's Pre-Flight engine now inspects the file extension, syntax tokens, and magic bytes, automatically injecting the runtime (`python3`, `node`, `ruby`, `php`, `bash`) into `childArgs`.
- **Multi-Language Verification:** Verified zero-config execution across Python, Node.js, Ruby, PHP, GNU Bash, and host glibc ELF binaries (`/bin/ls`).
- **4-Tier Image Resolution:**
  1. *Tier 1 (Sub-millisecond Cache):* Direct lookup in `$HOME/.silo/images/`.
  2. *Tier 2 (Streaming Tarball Downloads):* Pulls official base rootfs (Alpine, Debian/Ubuntu glibc) with direct HTTP-to-tar streaming (zero temp files).
  3. *Tier 3 (On-Demand Synthesis):* Synthesizes language runtimes on top of base Alpine using `chroot` and `apk add` without needing external registries.
  4. *Tier 4 (Offline Fallback):* Gracefully degrades to local `/tmp/silo-container/rootfs` if network is unreachable.
- **Kernel Discovery (OverlayFS UsrMerge Symlink Conflict):**
  - *The Bug:* In Debian/Ubuntu, `/bin` is a symlink to `usr/bin`. Injecting into `upperdir/bin` created a directory that shadowed and broke the lowerdir symlink, causing `/bin/bash` to disappear.
  - *The Fix:* Silo now checks `os.Readlink(lowerdir + "/bin")`. If it's a symlink to `usr/bin`, it injects into `upperdir/usr/bin/`, preserving all system symlinks seamlessly.

## 5. Volume Mounts, Secure `/dev` & Cleanup Protection (v0.3.2)
- **Ergonomic Volume Mounting (`-v` & `-w`):**
  - Implemented bare `-v` shorthand auto-binding current working directory `$(pwd)` to `/workspace` and defaulting working directory to `/workspace`.
  - Implemented explicit syntax: `-v <host>:<container>[:ro]` with relative path resolution.
  - Enforced the Linux two-step remount dance on `:ro` volumes (`MS_BIND` + `MS_REMOUNT|MS_RDONLY|MS_NOSUID|MS_NODEV`) to ensure read-only immutability.
- **OCI-Compliant `/dev` Virtual Filesystem:**
  - Mounted an isolated `tmpfs` on container `/dev` for all runs, avoiding host hardware device exposure while providing:
    - Safe character devices: `/dev/null`, `/dev/zero`, `/dev/full`, `/dev/random`, `/dev/urandom`, `/dev/tty`.
    - `/dev/shm` (POSIX shared memory `tmpfs`, mode=1777) for multiprocessing and tensors.
    - POSIX standard stream symlinks: `/dev/fd`, `/dev/stdin`, `/dev/stdout`, `/dev/stderr`.
- **Mount Safety & Unmount Guard:**
  - Prevented catastrophic `os.RemoveAll` host deletions by explicitly invoking `syscall.Unmount(mergedDir, syscall.MNT_DETACH)` prior to cleanup and restricting removals to scratch spaces (`upper/` and `work/`).
- **Verification:** Verified multi-file project execution, working directory switching, host disk persistence on intentional file writes, and kernel rejection of writes on `:ro` volumes.
