# Devlog: November 17, 2026

## 1. Context & Architectural Discussions
- **OverlayFS vs. CageFS:** Explored why container runtimes use OverlayFS (ephemeral copy-on-write union mounts) rather than the CageFS model (per-user bind-mounted skeleton templates used in shared web hosting).
- **The Dynamic Linker Dilemma:** Analyzed why binaries compiled on glibc systems (Ubuntu/Debian) fail with cryptic "not found" errors when executed inside musl systems (Alpine). The kernel cannot locate the interpreter specified in the binary's ELF header (`/lib64/ld-linux-x86-64.so.2` vs `/lib/ld-musl-x86_64.so.1`).
- **Smart ELF Auto-Detection Idea:** Outlined using Go's `debug/elf` standard library to inspect target binary headers (`PT_INTERP`) before launching containers to automatically match the binary to the correct rootfs or warn developers.
- **Rootless (`CLONE_NEWUSER`) Strategy:** Confirmed that leaving Rootless to v0.4 is optimal. Our Linux 6.8 kernel natively supports unprivileged OverlayFS mounts, and our modular structure allows adding `CLONE_NEWUSER` and UID/GID mappings without modifying the storage layer.

## 2. Dev Script: `scripts/setup_rootfs.sh`
Created an automated, robust script for downloading and unpacking the Alpine base image, fixing several edge cases:
- **Dynamic Architecture Mapping:** Auto-detects `x86_64` vs `aarch64` (`arm64`) using `uname -m`.
- **Dependency Minimization:** Validates archive integrity using `tar -tzf` instead of relying on an external `file` binary.
- **Atomic Extraction:** Avoids bash globbing errors on empty directories by cleanly recreating the directory.
- **Orphan Cleanup:** Added bash `trap` to delete `.tmp` download files if interrupted by Ctrl+C.

## 3. The "Live Thinking Engine" (`silo-core/thought.go`)
- **Problem:** Container runtimes like Docker and runc are opaque black boxes that leave beginners in the dark about kernel operations.
- **Solution:** Created an educational trace logger that writes annotated "thoughts" to `stderr` in real time, explaining each kernel subsystem transition (mount flags, cgroup allocations, OverlayFS assembly, pivot_root, and exec).

## 4. OverlayFS Implementation (`silo-core/overlay.go`)
- **Ephemerality Achieved:** Addressed the issue where container changes and `.ash_history` persisted in the base rootfs. Containers now pivot into an ephemeral OverlayFS `merged` directory.
- **Per-Container Topology:** Every container gets a unique instance sandbox: `/tmp/silo/instances/inst-<id>/` with dedicated `upper/`, `work/`, and `merged/` directories.
- **Zero Host Mount Pollution:** Mounted strictly *inside* the container's private mount namespace (`CLONE_NEWNS`). When the container exits, crashes, or gets OOM-killed, the mount is destroyed automatically by the kernel with zero stale mounts on the host.
- **Zero Storage Duplication:** Confirmed that `lowerdir` is never copied or duplicated on disk; the kernel shares read-only VFS inodes across all running containers.
