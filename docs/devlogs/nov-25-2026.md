# Devlog: November 25, 2026

## 1. Cross-Machine Rootless Audit: Why Fresh Hosts Still Needed `sudo`
Real-world testing on a second Linux machine surfaced the exact two-gate kernel sequence that blocked unprivileged `silo run`:
1. **Sysctl Gate (`kernel.unprivileged_userns_clone = 0` / `user.max_user_namespaces = 0`):** On Debian/hardened kernels, if unprivileged user namespaces are disabled globally at the sysctl layer, the kernel immediately rejects `CLONE_NEWUSER` with `EPERM` before AppArmor is even consulted.
2. **Ubuntu AppArmor Gate (`kernel.apparmor_restrict_unprivileged_userns = 1`):** Even with sysctl enabled, missing `/etc/apparmor.d/silo` or hardcoded path globs (`/{usr/local/bin,home/*/*}/silo`) failed whenever a user ran `silo` from arbitrary paths (such as `~/Downloads/silo` or `~/.local/bin/silo`).
3. **Why `setuid` Root Is Not an Option for Go:** Unlike tiny C wrappers (`bwrap`, `newuidmap`), Go binaries spawn multiple background OS threads (`sysmon`, GC) and read environment variables before `main()` runs—making `setuid` Go binaries a privilege-escalation risk. Silo must remain unprivileged and configure host prerequisites cleanly.

## 2. `silo wrench`: Kernel Diagnostics & One-Time Rootless Remediation (`v0.4.1`)
Implemented [silo-core/wrench.go](file:///home/codegrey/silo/silo-core/wrench.go), wired into [silo-core/main.go](file:///home/codegrey/silo/silo-core/main.go) and [silo-core/host.go](file:///home/codegrey/silo/silo-core/host.go):
- **Live 1ms Kernel Probe (`__probe-userns`):** Rather than parsing AppArmor configs with brittle regexes, `probeUserNamespace()` spawns `/proc/self/exe __probe-userns` with `CLONE_NEWUSER` and UID/GID mappings to verify whether the exact running binary clears both sysctl and AppArmor gates.
- **Full Readiness Check (`silo wrench` / `silo wrench check`):** Audits Linux kernel version (`>= 5.11` for unprivileged OverlayFS), `kernel.unprivileged_userns_clone`, `user.max_user_namespaces`, `apparmor_restrict_unprivileged_userns` + `/proc/self/attr/current`, Cgroups v2 `user@<uid>.service` slice controller delegation (`memory`, `pids`), `systemd-run`, and `~/.silo` / `/tmp/silo-<uid>` ownership.
- **Automated Scoped Fix (`silo wrench fix [-y|--yes]`):**
  - Resolves the binary's canonical path via `os.Executable()` + `filepath.EvalSymlinks()`.
  - Detects host AppArmor ABI (`4.0` vs `3.0` under `/etc/apparmor.d/abi/`) for cross-distro portability.
  - Writes `/etc/sysctl.d/99-silo-userns.conf` (only if sysctl blocks `userns`) and `/etc/apparmor.d/silo` scoped strictly to the binary path with `userns,`, keeping system-wide AppArmor protection enabled.
  - Restores ownership on any root-owned `~/.silo` or `/tmp/silo-<uid>` directories and re-runs the live probe immediately to verify success.
- **Seamless `silo run` Auto-Recovery:** Extracted `newContainerCmd()` in `host.go` so that when `CLONE_NEWUSER` hits `EPERM` on an interactive TTY, Silo displays the exact `wrench` diagnosis, offers one-time `sudo` setup (`[y/N]`), and automatically retries launching the container without requiring the user to re-type their command.

## 3. Critical Bug Discovered & Fixed: Rootless Language Image Synthesis (`__synth`)
Running the E2E suite from an empty image cache exposed a hidden rootless bug in [silo-core/image.go](file:///home/codegrey/silo/silo-core/image.go):
- **Failure:** Previously, `synthesizeLanguageImage()` invoked `exec.Command("chroot", targetRootfs, "/sbin/apk", "add", ...)` directly on the host, which requires `CAP_SYS_CHROOT` and failed with `Operation not permitted` in rootless mode. Worse, because `cp -a` copied base Alpine into `targetRootfs` before `chroot` ran, the failed step left behind an incomplete `python`/`node` directory containing `/bin/sh`—causing `isRootfsValid()` to report a valid cached image even though `python3`/`node` were never installed.
- **Resolution:**
  - Switched `synthesizeLanguageImage()` to an atomic staging directory (`rootfs.tmp` cleaned up on error and renamed to `rootfs` only on success).
  - Added an internal `__synth` child entrypoint (`runSynthChild`) spawned inside `CLONE_NEWUSER | CLONE_NEWNS` with isolated `/dev` (`setupDev`) and `/run/systemd/resolve/resolv.conf` DNS fallback, executing `/sbin/apk add --no-cache --no-chown` cleanly without root privileges.
