# Devlog: November 16, 2026

## 1. Architectural Refactor & Go Modules
- **Modularization:** Split `silo-core/main.go` into three dedicated files:
  - `main.go`: Entrypoint and CLI routing.
  - `host.go`: Host-side process management, namespace flags, signal proxying, timeout enforcement, and exit-code propagation.
  - `container.go`: In-namespace container initialization, private mount propagation, `pivot_root`, `/proc` mounting, and `syscall.Exec`.
- **`go.mod` Initialization:** Initialized root `go.mod` to allow multi-file compilation without having to pass individual `.go` files to `go build`.

---

## 2. Cgroups v2 Implementation (v0.2 Milestone)
- **Per-Container Scoping:** Used `/sys/fs/cgroup/silo-<pid>` instead of a global cgroup to avoid collisions when running concurrent containers.
- **Resource Constraints Applied:**
  - Memory: Capped at 50 MB (`memory.max = 52428800`).
  - Swap: Disabled swap evasion (`memory.swap.max = 0`).
  - Process limit: Capped at 50 max processes (`pids.max = 50`) for fork-bomb protection.
- **Controller Inheritance:** Implemented `ensureSubtreeControllers()` to enable `+memory +pids` in `/sys/fs/cgroup/cgroup.subtree_control` if not already inherited by child cgroups.
- **Orphan Process Cleanup:** Wrote `1` to `cgroup.kill` before calling `os.Remove()`. This forces the kernel to terminate any lingering background threads, preventing `EBUSY` errors during `rmdir`.
- **Deferred Cleanup Guarantee:** Refactored `run()` to return an `exitCode int` to `main()`, ensuring `defer cleanup()` executes before `os.Exit()`, preventing leaked cgroup directories on crash.

## 3. Encountered Edge Cases & Discoveries

### A. The 404 Rootfs Tarball
- **Event:** `tar -xvf` failed with "not in gzip format".
- **Cause:** `alpine.tar.gz` was downloaded without `-L` or with a mismatched URL, saving a 153-byte HTML 404 error page.
- **Solution:** Used `curl -fsSL -o alpine.tar.gz <URL>` so curl fails immediately on HTTP errors instead of saving HTML.

### B. Missing `/dev` in Minirootfs & Busybox `head`
- **Event:** Attempted to test memory limit with `head -c 60M /dev/zero | tail`.
- **Observations:**
  1. Busybox `head` only accepts raw byte numbers, rejecting unit suffixes like `60M`.
  2. Alpine minirootfs ships with an empty `/dev` directory. No `/dev/zero`, `/dev/null`, or device nodes exist yet because container runtimes typically mount a `tmpfs` at `/dev` and populate it via `mknod` or bind-mount host nodes.
- **Solution:** Tested memory exhaustion directly in shell using in-memory string doubling:
  `x=a; while true; do x=$x$x; done`
  When variable `x` crossed 50 MB, the kernel OOM killer immediately terminated the process with exit code 137.

## 4. Built-in Catastrophe Diagnostic Post-Mortem
- **Problem:** When a container was OOM-killed, Silo only printed `exit status 137` and deleted the cgroup directory, discarding all diagnostic evidence.
- **Solution:** Added `inspectCgroup(pid)` in `silo-core/cgroups.go`, invoked prior to cgroup teardown when `cmdErr != nil`:
  - Inspects `memory.events` for `oom_kill` and `max` throttle counts.
  - Inspects `memory.peak` to determine the maximum memory reached before death.
  - Inspects `pids.events` for `max` breach counts (fork bombs).
  - Emits a clean diagnostic post-mortem banner directly in the terminal before cleaning up the cgroup.

---

## 5. The Ephemerality Gap & Next Step: OverlayFS (v0.3)
- **Observation:** In a new container session, pressing the UP arrow in the shell recalled the previous container's command history (`.ash_history`).
- **Discovery:** `pivot_root` isolates the directory hierarchy and prevents escapes, but it is **not copy-on-write**. Any file created, modified, or written (like shell history or rootfs changes) permanently mutates `/tmp/silo-container/rootfs`.
- **Next Step:** Implement **OverlayFS (v0.3)**:
  - Base Alpine image mounted read-only as `lowerdir`.
  - Ephemeral per-container directory mounted as `upperdir` (discarded on container exit).
  - Container pivots into the `merged` view, ensuring 100% ephemeral isolation.
